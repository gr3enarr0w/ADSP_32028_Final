EXECUTIVE SUMMARY
================================================================================

The FAQ auto-generation pipeline consists of three sequential stages:

  1. ANALYZE    → Runs Gemini gap analysis on resolved tickets
                  Outputs: kb_coverage table (themes + priority)

  2. GENERATE   → Creates FAQ articles from identified gaps
                  Outputs: generated_articles table (status='draft')

  3. PUBLISH    → Pushes drafts to Confluence + indexes to kb_articles
                  Outputs: Confluence pages + kb_articles table

Access/Permissions FAQs not appearing indicates a block in one or more stages.

================================================================================
PIPELINE ARCHITECTURE
================================================================================

STAGE 1: Gap Analysis (faq/analyzer.py:69-189)
──────────────────────────────────────────────

  Input:   ticket_classifications + tickets tables
           - Only processes resolved tickets (t.resolution NOT NULL)
           - Requires has_resolution=1 classification flag

  Process: Groups tickets by (issue_type, category)
           Calls Gemini to identify coverage gaps

  Output:  kb_coverage table with:
           - theme: Topic name
           - coverage_status: missing|partial|covered
           - article_priority: high|medium|low
           - ticket_count: Matches for this theme
           - assessed_at: Last analysis timestamp

  Trigger: python faq_service.py analyze


STAGE 2: FAQ Generation (faq/generator.py:213-358)
──────────────────────────────────────────────────

  Input:   kb_coverage where coverage_status IN ('missing','partial')
           (Ordered by priority, ticket_count DESC)

  Process: For each gap:
           1. Fetch source tickets (3 strategies):
              - Exact issue_type match from sample_issue_types
              - Category match (fallback)
              - Keyword search in theme name
           2. Check for duplicates:
              - Title-level semantic (cosine > 0.82)
              - Structural fingerprint (HTML exact match)
              - Body semantic (cosine > 0.75)
           3. Call Gemini to generate FAQ (JSON → HTML)
           4. Store in generated_articles (status='draft')

  Skip if: • No source tickets found (line 147-149)
           • Title-level semantic duplicate (line 297-304)
           • Structural duplicate (line 306-311)
           • Semantic duplicate (line 313-323)
           • Gemini generation error (line 208-210)

  Output:  generated_articles table with:
           - article_topic: Theme name
           - title: FAQ question
           - body_html: Rendered answer
           - status: draft
           - format: faq
           - confluence_page_id: NULL (until published)

  Trigger: python faq_service.py generate [--theme NAME]


STAGE 3: Publishing (generation/publisher.py:49-109)
────────────────────────────────────────────────────

  Input:   generated_articles where status='draft' AND format='faq'

  Process: For each article:
           1. POST to Confluence v2 API
           2. Resolve space key → numeric ID
           3. Create page in space (parented if PARENT_PAGE_ID set)
           4. Update article status='published', store page_id

  Fails if: • Confluence space not found (line 64-66)
            • Auth 401 → Clear cache + retry (line 82-86)
            • API error (line 107)

  Output:  Confluence pages + generated_articles.confluence_page_id
           (Note: kb_articles indexing happens separately)

  Trigger: python faq_service.py publish [--space SPACE_KEY]

================================================================================
ROOT CAUSE ANALYSIS (Ordered by Probability)
================================================================================

ISSUE 1: Gap Analysis Never Ran [HIGHEST PROBABILITY]
───────────────────────────────────────────────────

  Symptom:  kb_coverage table empty or has 0 Access/Permissions entries

  Check:    SELECT COUNT(*) FROM kb_coverage
            WHERE theme ILIKE '%access%' OR theme ILIKE '%permission%';

  Expected: > 5 (at least a few themes identified)

  If 0:     Gap analysis has never executed

  Fix:      python faq_service.py analyze


ISSUE 2: Insufficient Resolved Tickets with resolution_summary
──────────────────────────────────────────────────────────────

  Symptom:  kb_coverage exists but ticket_count very low (< 5 per theme)

  Check:    SELECT tc.category, COUNT(*) as resolved,
                   COUNT(t.resolution_summary) as with_summary
            FROM ticket_classifications tc
            JOIN tickets t ON t.ticket_key = tc.ticket_key
            WHERE tc.category IN ('Access','Permissions')
              AND t.resolution IS NOT NULL
            GROUP BY tc.category;

  Expected: with_summary > 0 (at least some tickets have summaries)

  If 0:     • Ingest not populating resolution_summary
            • Tickets not marked as resolved in JSM
            • Classification not setting has_resolution=1

  Fix:      Verify ingest/tickets.py is extracting resolution_summary


ISSUE 3: Generator Silently Skipping Gaps (No Source Tickets)
─────────────────────────────────────────────────────────────

  Symptom:  kb_coverage has Access/Permissions themes, but no generated_articles
            Log shows: "No source tickets for theme: X"

  Check:    SELECT COUNT(*) FROM kb_coverage
            WHERE coverage_status IN ('missing','partial')
              AND theme NOT IN (
                SELECT article_topic FROM generated_articles WHERE format='faq'
              );

  If > 0:   Generator is being skipped

  Cause:    • sample_issue_types doesn't match actual classifications
            • Keyword extraction filters out theme words
            • Category mismatch between gap and tickets

  Fix:      Debug single theme manually:
            python faq_service.py generate --theme "Your Theme"


ISSUE 4: Semantic Duplicate Detection Too Aggressive
───────────────────────────────────────────────────

  Symptom:  Log shows: "Skipping semantic-duplicate FAQ"
            Generator runs but doesn't increase generated_articles count

  Check:    grep "Skipping.*duplicate" /path/to/logs

  Cause:    • FAQ already generated in previous run
            • Title or body cosine similarity > threshold
            • LLM generates synonymous theme names (e.g.,
              "Notification Behavior in Cloud" vs
              "Notification Management & Issues")

  Fix:      Lower DEDUP_COSINE_THRESHOLD in config.py
            Current: 0.75
            Try: 0.70 or 0.65


ISSUE 5: Gemini Generation Errors
──────────────────────────────────

  Symptom:  Log shows: "Failed to generate FAQ entry for X"
            Errors increase in error_count

  Check:    oc logs -n jira-messaging--runtime-ext $POD | grep "Failed to generate"

  Cause:    • API timeout (14-minute limit at line 195)
            • Model unavailable
            • Quota exceeded
            • Malformed prompt

  Fix:      • Increase timeout (line 195 of generator.py)
            • Check Gemini API quotas
            • Batch generate smaller gaps
            • Check GEMINI_MODEL_GENERATION env var


ISSUE 6: Articles Published But Not Indexed
──────────────────────────────────────────

  Symptom:  published_at set, confluence_page_id exists, but kb_articles empty

  Check:    SELECT COUNT(*) FROM generated_articles
            WHERE format = 'faq' AND status = 'published';

            SELECT COUNT(*) FROM kb_articles
            WHERE topics_covered ILIKE '%access%';

  If first > 0 but second = 0:  Indexing job hasn't run

  Fix:      Run indexing: python -m analysis.indexer (if exists)
            Or check if separate indexing process is needed
