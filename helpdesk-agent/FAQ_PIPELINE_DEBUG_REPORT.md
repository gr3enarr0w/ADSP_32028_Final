# FAQ Pipeline Debug Report: Access/Permissions Ticket Gaps

## Executive Summary

The FAQ auto-generation pipeline has three stages:

1. **Analyze** (`faq/analyzer.py`): Identifies coverage gaps using Gemini + ticket patterns → stores in `kb_coverage` table
2. **Generate** (`faq/generator.py`): Converts gaps into FAQ articles → stores in `generated_articles` table  
3. **Publish** (`generation/publisher.py`): Publishes drafts to Confluence → updates `confluence_page_id`

Access/Permissions FAQs not appearing suggests a block in one of these stages.

---

## How the Pipeline Works

### Stage 1: Gap Analysis (`analyze_faq_gaps`)

**Input**: Resolved tickets from `ticket_classifications` grouped by `(issue_type, category)`

**Logic** (lines 80-88 of `analyzer.py`):
```python
SELECT c.issue_type, c.category, COUNT(*) as cnt,
       SUM(CASE WHEN c.has_resolution = 1 THEN 1 ELSE 0 END) as resolved
FROM ticket_classifications c
JOIN tickets t ON t.ticket_key = c.ticket_key
WHERE t.source = 'cloud'
GROUP BY c.issue_type, c.category
```

**Outputs to `kb_coverage`**:
- `theme`: Topic name (generated by Gemini)
- `coverage_status`: `missing` | `partial` | `covered`
- `article_priority`: `high` (>15 tickets OR open bugs) | `medium` (5-15 tickets) | `low` (<5)
- `ticket_count`: Number of tickets matching this theme

**Critical Detail**: Analysis only runs if:
- `ticket_classifications.has_resolution = 1` (resolved with classification)
- `ticket_classifications.category` matches the theme
- Tickets exist with non-empty `resolution_summary` field

---

### Stage 2: FAQ Generation (`generate_all_faq_entries`)

**Input**: Gaps from `kb_coverage` where `coverage_status IN ('missing', 'partial')`

**Logic** (lines 229-235 of `generator.py`):
```python
gaps = conn.execute("""
    SELECT * FROM kb_coverage
    WHERE coverage_status IN ('missing', 'partial')
    ORDER BY
        CASE article_priority WHEN 'high' THEN 0 WHEN 'medium' THEN 1 ELSE 2 END,
        ticket_count DESC
""").fetchall()
```

**Then for each gap**:

1. **Fetch source tickets** using three strategies (lines 102-143):
   - Strategy 1: Exact `issue_type` match from `sample_issue_types`
   - Strategy 2: `category` match (fallback if not enough tickets)
   - Strategy 3: Keyword search in theme name vs. ticket summaries
   
   **Minimum**: Requires at least some resolved tickets with `resolution_summary`

2. **Check for duplicates** (lines 292-323):
   - Title-level semantic dedup (threshold 0.82)
   - Structural fingerprint dedup (exact HTML match)
   - Semantic cosine dedup (threshold 0.75)
   
   **Skip** if similar FAQ already exists

3. **Generate** via Gemini (lines 191-206):
   - Uses `FAQ_PROMPT` template
   - Generates JSON with `topic`, `question`, `answer`, `steps`, `known_limitations`

4. **Store** in `generated_articles` as `status='draft'` (lines 327-350)

**Critical Detail**: Generation skips a gap if:
- No source tickets found (line 149)
- Title-level semantic duplicate detected (line 303)
- Structural duplicate detected (line 310)
- Semantic duplicate detected (line 316)
- Gemini generation fails (line 209)

---

### Stage 3: Publishing (`publish_article`)

**Input**: Articles from `generated_articles` where `status = 'draft'` and `format = 'faq'`

**Logic** (lines 49-109 of `publisher.py`):
1. Resolve Confluence space key to numeric ID
2. POST to `/wiki/api/v2/pages` with article HTML
3. Update `confluence_page_id`, `confluence_url`, `status = 'published'`

**Can fail** if:
- Confluence space not found (line 65)
- Auth issues (401 — cleared + retry at line 82)
- API errors (line 107)

## Likely Causes (in order of probability)

### 1. **Gap Analysis Never Ran** (Highest likelihood)
- `kb_coverage` table is empty or missing Access/Permissions entries
- **Fix**: Run `python faq_service.py analyze` manually

### 2. **Insufficient Resolved Tickets with `resolution_summary`**
- Access/Permissions tickets exist but lack `resolution_summary` field
- **Symptom**: `kb_coverage` has low `ticket_count` (< 5)
- **Root cause**: 
  - Tickets not marked as resolved in JSM
  - `resolution_summary` not being populated by ingest/tickets.py
  - Classification not setting `has_resolution = 1`
- **Fix**: Verify tickets have `resolution IS NOT NULL` and `resolution_summary` populated

### 3. **No Tickets Matching Theme Keywords**
- Generator's three strategies fail to find source tickets
- **Symptom**: Articles skipped silently (line 147-149: "No source tickets for theme")
- **Root cause**:
  - `sample_issue_types` in gap doesn't match actual ticket classifications
  - Keyword extraction fails (line 129-132: keyword filtering excludes theme words)
- **Fix**: Manually generate with `--theme` flag to debug single gap

### 4. **Semantic Duplicate Detection Too Aggressive**
- FAQ generated once, then blocked on second pipeline run
- **Symptom**: Log shows "Skipping semantic-duplicate FAQ" (line 319)
- **Root cause**: Title/body cosine similarity > threshold
- **Fix**: Lower `DEDUP_COSINE_THRESHOLD` in config.py (currently 0.75)

### 5. **Gemini Generation Errors**
- API timeouts or model unavailable
- **Symptom**: Errors logged at line 209
- **Root cause**: Timeout (14 min at line 195) insufficient, or quota exceeded
- **Fix**: Check Gemini quotas, increase timeout, or batch smaller gaps

### 6. **Article Published but Not Indexed**
- FAQs exist in `generated_articles` and Confluence, but `kb_articles` table not updated
- **Symptom**: Published FAQs not showing in lookups
- **Root cause**: `kb_articles` indexing not run after publish
- **Fix**: Run indexing job: `python -m analysis.indexer` (if it exists)

```sql
SELECT category, COUNT(*) as resolved_cnt,
       COUNT(resolution_summary) as with_summary
FROM ticket_classifications tc
JOIN tickets t ON t.ticket_key = tc.ticket_key
WHERE tc.category IN ('Access','Permissions')
  AND t.resolution IS NOT NULL
GROUP BY category;
```
**Expected**: > 0 in `with_summary` column

### Check if generation is being skipped:
```sql
SELECT COUNT(*) FROM kb_coverage
WHERE coverage_status IN ('missing', 'partial')
  AND theme NOT IN (
    SELECT article_topic FROM generated_articles WHERE format = 'faq'
  );
```
**Expected if blocked**: > 5


## Pipeline Execution Flow

```
┌─────────────────────────────────────────────────────────────────────┐
│ 1. ANALYZE: Fetch tickets + Gemini gap analysis                      │
│    Input: ticket_classifications (resolved, with has_resolution=1)   │
│    Output: kb_coverage (themes + priority + coverage_status)         │
└──────────────────────────┬──────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 2. GENERATE: Convert gaps to FAQ articles                            │
│    Input: kb_coverage (missing/partial)                              │
│    Steps:                                                             │
│      - Fetch source tickets (3 strategies)                           │
│      - Check duplicates (title, structural, semantic)                │
│      - Gemini generation (JSON → HTML)                               │
│    Output: generated_articles (status='draft', format='faq')         │
│    Skip if: no source tickets OR duplicate detected OR Gemini error  │
└──────────────────────────┬──────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 3. PUBLISH: Confluence push + kb_articles indexing                  │
│    Input: generated_articles (status='draft')                        │
│    Output: Confluence pages + kb_articles (indexed)                  │
│    Can fail: Space not found, auth, API errors                       │
└──────────────────────────┬──────────────────────────────────────────┘
                           │
                           ▼
            ✓ FAQ articles in kb_articles (searchable)
            ✓ Confluence pages published
```
