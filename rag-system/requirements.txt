# langchain-anthropic/langchain-openai are pinned <1.0.0 because ragas 0.3.x's own `langchain` dependency
# pulls langchain-core down to the 0.3.x line, and langchain-anthropic/langchain-openai >=1.0 require

# without this pin, `from langchain_anthropic import ChatAnthropic` raises ImportError at runtime.
# (only one of the two is strictly required at runtime depending on which judge the user configures —
# pin both since either may be selected)

# langchain-google-vertexai is pinned <3.0.0 for the same reason: 3.0.0+ requires langchain-core>=1.0.0,
# which conflicts with the langchain-core 0.3.x line that ragas 0.3.x's own `langchain` dependency pulls
# in (same class of conflict as the langchain-anthropic/langchain-openai pins above) — confirmed via a
# live pip install in this environment. It's used as the Vertex AI fallback for both the judge LLM
# (ChatAnthropicVertex) and judge/answer-relevancy embeddings (VertexAIEmbeddings) when ANTHROPIC_API_KEY
# / OPENAI_API_KEY aren't set but ANTHROPIC_VERTEX_PROJECT_ID is.
#

# transitively via langchain-anthropic) because the `[vertex]` extra — needed for
# `from anthropic import AnthropicVertex` — is easy to miss with a plain `pip install anthropic`.
#
# langchain-ollama is pinned to exactly 0.3.10 for the same class of issue as the other langchain-*
# pins above: a plain `pip install langchain-ollama` (no version pin) resolves to 1.1.0+, which
# requires `langchain-core>=1.4`, dragging langchain-core off the 0.3.x line that ragas 0.3.x's own
# `langchain` dependency (and langchain-anthropic/langchain-openai/langchain-google-vertexai, all
# pinned <1.0.0/<3.0.0 above) require — this breaks the whole judge-LLM stack with `pip check`
# reporting langchain-core version conflicts across langchain, langchain-anthropic, and
# langchain-openai. langchain-ollama==0.3.10 requires `langchain-core<2.0.0,>=0.3.76`, which is
